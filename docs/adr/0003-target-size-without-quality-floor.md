# 目标体积优先，不为画质或尺寸设下限

用户把“≤ 目标体积”视为硬结果：先降编码质量，仍超标再缩小像素尺寸，直到达标。首版不设质量下限、也不设最小长边；失败只留给编码错误、格式不支持、动图、或目标体积低于最小可编码体积。

**备选方案**：质量 40 / 长边 320 的下限（更能保画质，但激进目标会失败）；质量 60 / 长边 640（画质优先，失败更多）；不设下限（选择项）。

**后果**：为了“几乎总能达标”，结果可能被压到明显模糊甚至极小尺寸。队列必须在不阻断输出的前提下显式提示极端降级（如质量过低或长边过小），否则就变成了静默降质。目标体积与用户指定的宽高上限盒冲突时，体积优先，尺寸可继续缩小；若目标体积小到任何编码都无法满足，则该文件失败且不输出。
