# 处理结果先进暂存区，下载是唯一落盘出口

客户反馈：中年用户不理解「输出到源文件同目录」这类术语，也不希望处理完就往原图文件夹里写文件；他们熟悉的是手机式的「处理 → 自己点下载」。决定：**处理一律只把结果写进应用数据目录下的暂存区（`history/<一次处理>/`），原图所在文件夹零写入；用户点「下载 / 全部下载」时才复制到自己选的文件夹**（默认系统「下载」文件夹并记住上次选择，重名自动加 -2 不覆盖，「保留文件夹层级 / 文件名格式」成为下载时的选项）。

本决定**废止 D-12（默认输出同目录 `-out`）与 D-35（默认行为与历史版本逐字节一致）**——它们服务于「零配置直接落盘」的程序员心智，正是本次要改掉的对象；防覆盖、原子落位、命名渲染这些机制全部保留，只是触发点从「处理时」移到「下载时」。同时**修订 D-19**：为支撑「忘了下载还能再下」，引入有限的历史记录（暂存文件与元数据保留最近 30 次处理，可手动清空；更早的条目保留记录、不可再下载）——D-19 反对的「无限增长的历史数据负担」通过保留上限规避，并非推翻其初衷。

**备选方案**：处理时直接写用户选的目录（现状，被客户否决——默认不该动原图文件夹，且忘了设置就污染目录）；处理后仅存内存、下载时重新转换（源图可能被移动/删除，且重复转换浪费时间）；暂存 + 无上限历史（磁盘会被无声撑爆）。

**后果**：`config.json` 的 `image_output_mode / image_output_directory / image_output_pattern` 三字段废止（读取忽略、不再写入）；下载相关状态（已下载标记、上次下载目录）进数据库与配置；暂存区占用需要清理策略与「清空历史」出口。界面词汇同步全面口语化，术语以根目录 `GLOSSARY.md` 为单一真相（D-57）。
