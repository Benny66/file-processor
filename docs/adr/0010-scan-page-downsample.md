# 扫描页默认压到 150 DPI（修订 ADR-0009 的「不缩像素」）

对标业内 PDF 压缩（2026-10 调研）：Ghostscript 预设的**按 DPI 降采样**是业内最大杠杆（`/screen`=72、`/ebook`=150、`/printer`=300 DPI，高于阈值的图才缩），Acrobat 与各在线工具的三档强度本质上都是 DPI + JPEG 质量的预设组合；qpdf 级无损结构优化与 JPEG 重存我们已与业内持平且更稳（逐张「重存不更小就跳过」天然免疫业内预设无条件套用的翻车）。ADR-0009 的「不缩像素」承诺把最大的杠杆关在了门外——扫描件常按 300–600 DPI 存储，屏幕阅读只需 150。

决定（用户 2026-10-24 拍板）：**默认开启**满页扫描图降采样——仅当某页资源里恰有一张图像 XObject（直接引用，包在 Form 里的不算）、且图像长宽比与页面一致（±15%，/Rotate 90/270 已换轴）时认定为「图填满页面」的扫描页，此时有效 DPI 可从页面尺寸精确算出（无需解析内容流），高于 **150 DPI**（Ghostscript `/ebook` 同款，单一真相 `pdfScanDPIFloor`）才等比压到 150，随后仍走「质量 75 + 仅更小才替换」；统计单列 `ImagesDownsampled`，逐项消息如实转述「其中 x 张压到了屏幕清晰度」。JPEG 质量不分档（75 已是业内 Recommended 档甜点，多档位徒增普通用户负担）。实现要点：pdfcpu `ReadContext` 后 `PageCount` 为 0，须先 `EnsurePageCount` 再 `PageDict`，否则扫描识别静默失效（测试夹具逮住并修复）。

**备选方案**：降采样做成用户可选档（默认不缩，承诺零变化——被用户否决，倾向默认收益最大化）；任意图全量降采样（需要解析内容流的变换矩阵才能算真实显示尺寸，误伤插图风险高，只做安全子集）；单色图转 JBIG2 与字体子集化（纯 Go 无编码器/无实现，业内「极限档」的字体处理还会弄坏文字渲染，不做并在界面如实声明）。

**后果**：默认行为变化——同一扫描件 PDF 重跑会得到比 ADR-0009 时期更小、打印清晰度更低的产物（屏幕阅读不受影响）；文字/矢量内容仍字节级不动，非扫描页（插图、多图、72–150 DPI）完全不触发；ADR-0009 的其余承诺（质量下限、仅更小才替换、SMask 保留、加密/签名拒绝）不变。变更提案 `openspec/changes/compress-pdf/` 已同步修订。
