# 竞品对比与迭代建议（2026-10）

> 目的：以业内竞品为参照，找出图片工坊的功能差距与迭代方向。
> 主视角：**麒麟政企用户**（稳定、合规、可信 > 功能花哨）。
> 硬约束（不可动摇）：本地离线、无遥测、无 CGO、麒麟 V10 兼容——需要突破约束才能追平的差距单列 §5-D，**不进迭代建议**。
> 数据时点：竞品信息为 2026-10 网络公开调研（§7.2 附来源，`？`＝未查到、不代表没有）；
> 本产品功能面以当前代码与规格盘点为准（`docs/specs/2026-10-23-image-workshop.md` + 代码走查）。

## 1. 竞品集合与总结论

三层 8 款：**直接同类**（图压、Caesium、XnConvert、ImageOptim）、**交互标杆**（Squoosh、TinyPNG）、**商业对照**（嗨格式压缩大师、汇帮超级压缩器）。

**结论一：定位重合度最高的图压已死，空位真实存在。**
图压（「压到指定体积 + 指定宽高」双卖点，与图片工坊几乎完全同定位）最后版本 v0.4.1 停在 2020-10，至今 6 年无更新，格式停留在 JPG/PNG/GIF/SVG（无 WebP）。「指定体积压缩」这一用户心智由图片工坊接走的门槛极低——做一个 2026 年的现代版图压即可全面超越。

**结论二：活着的直接竞品只有 Caesium 同时具备「目标体积 + 三平台」。**
Caesium v2.8.5（2025）仍在维护且 v3 开发中，有目标体积模式（Size Mode）、元数据可选保留、保留文件夹结构、实时前后预览。它没有的——自定义输出体验、现代格式组合、信创/ARM 覆盖——就是图片工坊可扩的护城河。XnConvert 占「格式转换」维度（500+ 读入、AVIF/HEIC 可写、更新极勤）但**官方拒绝做目标体积压缩**（2015 年起的用户请求至今未实现）；ImageOptim 仅 macOS、功能面窄、三年未更新。

**结论三：全体竞品的公约数短板，恰好是图片工坊三合一的定位。**
无一同时具备「目标体积压缩 + WebP 等现代格式 + 麒麟/信创版本」；Squoosh 官方拒绝批量（多个 issue 关闭为 not_planned，2026-07 社区批量 PR 仍未合并）；TinyPNG 必须上传云端（隐私结构性软肋）；国内两款商业工具图片侧只覆盖传统格式、无格式转换，且「免费下载、保存要钱、强制登录」是口碑负资产。**本地离线 + 无登录无付费墙 + 目标体积 + 批量**的组合目前无人占据。

逐款要点（事实级，来源见 §7.2）：

- **图压**：输入输出 JPG/PNG/GIF/SVG；可调压缩强度；输出文件夹/文件名/格式可自定义；无 EXIF/ICC 选项说明；无 CLI、无文件夹监视；官网 tuya.xinxiao.tech（原 tuya.so 已失效）。
- **Caesium**：JPG/PNG/WebP/TIFF/BMP（HEIC 仅 macOS 读入、无 AVIF）；质量 0-100 / 目标体积 / 无损三模式；元数据可选保留（EXIF/GPS/ICC）；保留源文件夹结构；高级导入过滤（`pic:` 前缀）；压缩后可自动删源或移回收站；有 CLI（CaesiumCLT）与网页版；已知 bug：PNG options 失效（#330）、目标体积大于原文件时输出不变（#138）；**无 ARM Linux 官方构建**；作者明确定位「是压缩器不是转换器」，拒绝做格式转换。
- **XnConvert**：读取 500+（含 RAW/PSD）、导出约 70 种（含 AVIF/HEIC/WebP/PDF/PSD）；动图 GIF/APNG 读写；旋转/裁切/缩放/水印/滤镜全家桶，组合可存预设；元数据可编辑、保留可选；输出保留子文件夹结构 + 变量化重命名模板；多核并行；兄弟产品 nconvert CLI；**无目标体积压缩（最大痛点）**；UI 信息密集。
- **ImageOptim**：PNG/JPEG/动画 GIF/SVG 同格式再压缩，默认无损（Zopfli/MozJPEG 等工具链）；元数据全剥或全留、不能细粒度挑选；不能缩放、不能转格式、无目标体积；Finder 右键 Services 集成；AVIF 支持请求挂起 7 年（issue #305）。
- **Squoosh**：编解码器 MozJPEG/OxiPNG/WebP/AVIF/JXL(beta)/WP2(unstable)；**不支持批量**（官方多次关闭批量请求）；CLI 与 lib 已官方弃维护；交互见 §4。
- **TinyPNG**：JXL/AVIF/WebP/JPG/PNG/APNG（无 GIF）；smart lossy（选择性减色，宣称最高减 80%）；API resize 四法 scale/fit/cover/thumb（`fit` 与图片工坊宽高盒同语义、不放大小图）；API 可选保留 copyright/creation/location 三项元数据；图片上传服务器、保留最长 48 小时；Web 免费一次 20 张、单张 5MB。
- **嗨格式**：六品类（视频/图片/PDF/Word/PPT/GIF）；图片仅 png/jpg/bmp/tif 等传统格式、无转换能力；宣称离线压缩但完整功能需 VIP；黑猫平台有系列退款纠纷。
- **汇帮**：图片仅 JPG/PNG/BMP；宣称本地处理但保存需登录+会员；官方条款不支持退款；无 macOS/Linux。

## 4. 交互体验对比（五段工作流）

- **导入**：图片工坊处于第一梯队——整窗拖拽 + 递归扫描 + 跳隐藏/符号链接 + 去重 + 拒绝项带原因汇总 + 缩略图惰性检查，竞品未见更完整的导入体验。粘贴导入（Squoosh）是唯一未覆盖的入口，价值一般。
- **配置**：极简并列规则（格式/体积/盒可单可组）与图压同路线，比 XnConvert 的 Tab 式全参数面板对新手友好。差距在**反馈环**：Squoosh 改参数立即刷新体积与节省百分比，Caesium/XnConvert 有压缩前预览，图片工坊必须跑完批次才知道结果。
- **处理**：逐项状态机（待检查→检查中→排队→处理中→终态）+ 进度事件 + 当前张完成后取消 + 单张失败不中断，在桌面竞品中是最完整的一档；「极端降级」显式提示是独有项。固定 2 worker 相对 Caesium/XnConvert 的多核并行偏保守。
- **查看**：并排对比 + 透明棋盘格 + 方向归一预览超过国内工具，落后于 Squoosh 的分割线滑块 + 局部放大镜（查压缩伪影）与多编解码器 A/B。
- **取件**：**最弱一环**。结果固定写回源文件同目录（`-out` 命名），无自定义输出目录、无保留文件夹结构、无重命名模板——Caesium/XnConvert/图压三项全有。对政企「批量处理后集中归档/入库」的场景，这是当前体验与竞品差距最大的一段。

## 6. 迭代建议（P0–P3）

排序原则：**政企价值（能不能用 → 高频刚需 → 差异化）× 工程成本**；工作量 S（天级）/ M（周级）/ L（月级）粗估；全部条目均不破约束。**P0 不完成，其余都是在未验收的地基上叠功能。**

### P0 信任与可用门槛（政企「能不能用」）

> **2026-10-24 状态**：①真机验收因无硬件**挂起**；②按「个人+朋友分发」决策收窄——签名公证裁撤
> （证书不办），`.deb` 接入 tag Release、三平台安装指南与 `SHA256SUMS.txt` 校验和已实施，
> 见 `docs/specs/2026-10-24-p0-release-identity-plan.md`（v2）。

1. **麒麟真机验收闭环**（C1）。依据：ADR-0002 明示 001 未完成；README 已知限制。价值：唯一竞品无法快速跟进的平台故事必须先为真。工作量 S（代码已备，缺真机执行）。
2. **发布身份收口 + 签名公证 + `.deb` 进 Release**（C2）。依据：README 已知限制 4 项（bundle id 占位、module 名、未签名公证、tag 发布不含 deb）。价值：政企分发被 Gatekeeper/SmartScreen 拦截即不可用；也是「正式发布」的前置。工作量 M。

### P1 高频刚需追平（差距清单 A 的头部）

3. **自定义输出目录 + 保留源文件夹结构**（A1）。依据：Caesium/XnConvert/图压三项全有，图片工坊取件环节全面落后。价值：政务批量归档/入库的主路径。工作量 M。
4. **仅重跑失败项**（A3）。价值：大批量失败兜底，无需引入任务历史。工作量 S。
5. **重命名模板简版**（A2）。价值：`-out` 命名在大批量下管理成本高。工作量 S–M。

### P2 差异化超越（B 类）

6. **单张调参工作台 → 存为预设**（B1 + A7）。依据：Squoosh 交互验证 + 官方拒绝批量的真空位 + 图压遗孤用户最短路径。工作量 L。
7. **多格式竞速推荐**（B2）。依据：TinyPNG「下载最佳结果」先例；与目标体积天然契合（同体积比质量，或同质量比体积）。工作量 M。
8. **ARM64 Linux 构建（飞腾/鲲鹏）**（B3）。依据：竞品全无 ARM Linux；无 CGO 是独有结构性优势。工作量 S–M（构建侧）+ 真机验收。
9. **首屏隐私主张文案**（B4）。依据：Squoosh 先例，零风险高信任。工作量 S。

### P3 决策复议类（默认不做，列出触发条件）

10. **元数据可选保留**（A4，复议 D-13/D-26 派生）。触发：政企客户提出版权/档案字段保留需求。工作量 M。
11. **质量模式可选**（A6，复议 D-23）。触发：目标体积之外的高级用户诉求成规模。工作量 S–M。
12. **GIF 动图支持**（A8，复议 D-15 范围）。触发：动图占比高的用户反馈；纯 Go 技术可行。工作量 M。

### 不建议跟进项（明确不跟，避免被竞品带偏）

- **压缩后自动删源/移回收站**（Caesium 有）：与「永不覆盖源文件」的隐私安全承诺冲突，政企宁多勿删。
- **文件夹监视（watch folder）**：全体竞品均未做，场景弱。
- **水印/滤镜/脚本**（XnConvert 路线）：见 D5。
- **多品类扩展**（嗨格式/汇帮路线）：见 D3。
