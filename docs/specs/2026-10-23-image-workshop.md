# 图片工坊 / ImageWorkshop — 规格说明书

- 状态：已对齐（2026-10-23）
- 依据：`CONTEXT.md`、`docs/adr/0001~0004`、本轮共识
- 产出阶段：`grill-with-docs` 已完成；本文供 `to-tickets` 切分

## 1. 问题陈述

当前仓库是完整的 Wails v2 桌面基座，但没有任何图像处理能力；首页与设置仍是占位。用户需要在本地批量完成三件事：

1. 图片格式转换（JPEG / PNG / WebP）。
2. 把文件体积压到指定上限。
3. 把像素尺寸限制在指定宽高以内。

目标环境包含**银河麒麟桌面操作系统 V10 SP1（2203，x86_64）**，同时保留 macOS 与 Windows 交付。现有 Linux 构建链路只产出裸二进制、固定使用 `webkit2_41` 标签、且不在 CI 验证范围内，不能直接视为“支持麒麟”。用户要求本地处理，不上传图片，也不需要联网能力。

## 2. 方案概述

一个以**批量队列**为中心的图片处理工作台：

- 用户拖拽文件/文件夹或通过原生对话框导入图片，队列展示缩略图、原尺寸、原体积与状态。
- 用户在右侧统一设置输出格式、目标体积、宽高上限盒，然后显式点击“开始处理”。
- Go 侧纯 Go 图像引擎完成解码、方向归一、缩放、编码与目标体积搜索；service 编排批次并通过既有事件契约推送进度；前端渲染队列、结果与单张对比。
- 输出写在源文件同目录，使用 `-out` 后缀，永不覆盖源文件。
- 交付 macOS `.dmg`、Windows NSIS 安装器、Kylin `.deb`；Kylin 使用旧 glibc 容器（初始 `ubuntu:20.04`，按 spike 调整）近似构建加真机冒烟。

### 接缝（seam）

| 接缝 | 位置 | 职责 |
|---|---|---|
| 图像引擎 | 新增 `internal/imageproc` | 纯函数：探测、方向、缩放、编码、目标体积搜索；不碰数据库、不碰 UI |
| 批次编排 | `internal/service` | 文件扫描、去重、输出命名、并发、取消、进度事件、预设 CRUD |
| 绑定层 | `app.go` | 薄封装，只经 service；错误用 `apperr` |
| 管道契约 | `internal/event` + `frontend/src/lib/event.ts` | 复用 `<domain>:<action>`、进度/结束载荷与 `useEvent` |
| 数据 | `internal/model` + SQLite | 预设；上次设置进 `config.json` |
| 运行时能力 | `internal/dialog` / `reveal` / `config` / `logging` | 复用现有原生对话框、目录打开、配置与日志 |
| 前端 | `frontend/src/views/image/` + `stores/` | 工作台、队列、参数、对比、预设 |

刻意不新建第二套错误、事件、分页或日志通道；这些已有接缝直接复用。

### 绑定接缝草案

> 这是接口形状，不是实现细节；类型名可在实现时微调，但职责与边界不变。

| 绑定方法 | 输入 | 输出 / 语义 |
|---|---|---|
| `ScanPaths` | `paths []string, skip []string` | `ScanResult`：`files`（支持扩展名且可访问）+ `rejected`（不支持/不可访问/重复及原因）。`skip` 是队列已有绝对路径；不解码，保证导入快。 |
| `InspectImage` | `path string` | `ImageInfo`：内容探测格式、方向归一后的宽高、字节数、缩略图 base64、扩展名不一致 warning。动图/损坏/超限返回可读错误。 |
| `RenderPreview` | `path string, maxEdge int` | `Preview`：base64 data URL、宽高、是否含透明。用于单张对比。 |
| `PreviewConvert` | `path string, rules BatchRules` | 单张真实试算（2026-10-24，US-46）：返回真实输出体积/格式/尺寸/质量/标志位与输出像素的预览 data URL，**不落盘**；已达标返回 skipped；批次运行中返回 Conflict（D-41）。 |
| `ProcessBatch` | `BatchRequest`（items + rules + output，US-39~40） | 阻塞至批次结束并返回 `BatchResult`（**结果的唯一投递路径**）；期间发 `image:progress`，载荷含 `done`/`total`、`started`（刚被 worker 领取的项，US-14 的「处理中」来源）与 `current`（刚完成项的结果）。 |
| `ValidateImageRules` | `BatchRules`, `OutputPlan` | 「开始处理」前的预检：合法返回空串，否则返回可直接展示的中文原因（US-11）。范围与「至少一条规则」的判定只在 Go 写一份，前端不再复制逻辑与文案。 |
| `SupportedFormatHints` | — | 可导入格式的展示清单，由 `imageproc.supportedFormats` 投影，前端不手写清单。 |
| `CancelBatch` | — | 设置取消标记；在当前文件完成后生效。 |
| `ListPresets` | `page.Request` | `page.Result[model.ImagePreset]`（列表契约）。 |
| `SavePreset` / `DeletePreset` | 预设 / id | 预设 CRUD；名称唯一。 |
| `GetImageSettings` / `SaveImageSettings` | — / `ImageSettings`（规则 + 输出目的地） | 上次参数读写；落 `config.json`。 |

核心类型（字段可在实现时补充，语义不变）：

```go
type OutputFormat string // keep | jpeg | png | webp

type Rules struct {
    OutputFormat OutputFormat `json:"output_format"`
    TargetBytes  int64        `json:"target_bytes"` // 0 = 关闭
    MaxWidth     int          `json:"max_width"`    // 0 = 关闭
    MaxHeight    int          `json:"max_height"`   // 0 = 关闭
}

type ItemResult struct {
    Path            string `json:"path"`
    OutputPath      string `json:"output_path"`
    Status          string `json:"status"` // success | failed | skipped | canceled
    SourceBytes     int64  `json:"source_bytes"`
    OutputBytes     int64  `json:"output_bytes"`
    Width           int    `json:"width"`
    Height          int    `json:"height"`
    ExtremeDegraded bool   `json:"extreme_degraded"`
    Message         string `json:"message,omitempty"`
}

type BatchResult struct {
    OK              bool         `json:"ok"`
    Message         string       `json:"message,omitempty"`
    Items           []ItemResult `json:"items"`
    Success         int          `json:"success"`
    Failed          int          `json:"failed"`
    Skipped         int          `json:"skipped"`
    Canceled        int          `json:"canceled"`
    ExtremeDegraded int          `json:"extreme_degraded"`
    SavedBytes      int64        `json:"saved_bytes"`
}
```

事件沿用 `internal/event` 的动作常量与 `<domain>:<action>`，域为 `image`：`image:progress` 载荷含 `done`/`total`、`started`（处理中）与 `current`（完成项结果）。**批次结果不再另发 `image:done`**——`ProcessBatch` 是阻塞调用并返回完整 `BatchResult`，再发一次就是同一结果两条投递路径，前端只会订其中一条，另一条静默空转（005→011 累计审查的实际发现：`image:done` 发射了，全库无人订阅）。现由护栏 `TestEmittedEventsHaveSubscribers` 双向核对「Go 发射 ↔ 前端订阅」，只发不收即红。前端用 `eventName('image', ...)` 与 `useEvent`，不手写事件名。`OutputFormat` 与 `ItemStatus`（含 `processing`）的 Go 常量是单一真相，前端镜像由 `internal/guard/parity_test.go` 校验。

## 3. 用户故事

### A. 导入与队列

**US-01 拖拽文件导入**
- 当用户把一个或多个文件拖到窗口，支持格式的图片进入队列。
- 不支持的扩展名不进入队列，导入结果给出跳过汇总提示。
- 拖拽区域在空队列与有内容时都可用。

**US-02 拖拽文件夹递归导入**
- 当用户拖入文件夹，递归扫描其下所有图片。
- 扫描不跟随目录符号链接，跳过以 `.` 开头的隐藏文件与隐藏目录。
- 文件按路径排序后入队，保证同一文件夹多次导入顺序稳定。
- 同一绝对路径在队列中只出现一次。

**US-03 对话框导入**
- 提供“添加文件”（多选）与“添加文件夹”两个入口。
- 取消对话框不改变队列。

**US-04 队列信息**
- 每项显示：缩略图、文件名、原图宽高、原体积、当前状态。
- 悬停文件名可看到完整路径。
- 缩略图必须按拍摄方向正确显示。

**US-05 无效文件早期标记**
- 损坏文件、动图、超过安全上限的文件在检查阶段标记为失败，并显示原因。
- 扩展名与内容格式不一致时按内容格式处理，并在队列中提示，不视为失败。
- 失败项保留在队列中，可单独移除，不阻止批次启动。
- 被拒绝的文件以汇总提示呈现，不静默消失。

**US-06 移除与清空**
- 用户可移除单个待处理项或清空队列。
- 处理进行中禁止移除、清空与新增导入，避免队列与运行中的批次不一致。

**US-07 大目录导入不冻结界面**
- 导入大量文件时界面保持可响应，展示扫描/检查中的状态。
- 缩略图按队列可见项逐步加载，不要求一次性解码整批图片。

### B. 参数与预设

**US-08 输出格式**
- 可选：保持原格式、JPEG、PNG、WebP；2026-10-24 增补「自动（最小体积）」（US-49）。
- 保持原格式时，JPEG/PNG/WebP 沿用源格式；BMP/TIFF/静态 GIF 默认输出 PNG。
- 源格式以内容探测为准，扩展名只用于导入预筛。
- 选择 JPEG 时，透明图会在结果中铺白底并给出提示。

**US-09 目标体积**
- 可开启并输入正整数，单位支持 KB 与 MB（1 KB = 1024 bytes）。
- 合法范围 1 KB–1 GB；关闭时表示不限制体积。
- 目标体积与宽高盒可同时启用。

**US-10 宽高上限盒**
- 可开启并输入最大宽、最大高；范围 1–65535 px。
- 图片等比缩小到盒内，不裁切、不拉伸、默认不放大。
- 目标体积与尺寸盒冲突时，目标体积优先，尺寸可继续缩小。

**US-11 开始前校验**
- 至少存在一条有效规则（格式变更 / 目标体积 / 宽高盒）才能开始。
- 至少有一张可处理图片；批次未在进行中。
- 校验失败在界面内提示，不发起处理。

**US-12 预设**
- 用户可把当前参数保存为命名预设；预设存入 SQLite。
- 支持创建、应用、重命名、删除；名称去空白后不可重复。
- 应用预设只改变参数，不自动开始处理；已有结果标记为过期。

**US-13 上次设置**
- 应用重启后恢复上次使用的处理参数。
- 配置缺失或损坏时回退到默认值（保持原格式、目标体积关闭、宽高盒关闭），不阻断启动。

### C. 处理

**US-14 开始批次与进度**
- 点击“开始处理”后，每个文件经历：排队 → 处理中 → 成功 / 失败 / 已跳过 / 已取消。
- 界面显示完成数/总数与当前文件；处理期间界面可滚动、可查看结果。
- 批次结束后显示成功、失败、跳过、取消的数量。

**US-15 取消**
- 取消请求在当前文件完成后生效；当前文件若已完成则保留结果。
- 尚未开始的文件标记为已取消，不产出文件。
- 取消不留下临时文件或半个输出文件。

**US-16 输出命名与不覆盖（2026-10-24 修订，ADR-0007）**
- 处理结果先进暂存区（US-59），原图所在文件夹零写入；下载（保存）是唯一落盘出口。
- 下载时按文件名格式渲染名称（默认 `<原名>-out`）；目标名已存在依次追加 `-2`、`-3`，任何情况下都不覆盖已有文件。
- 保存位置 / 保留文件夹层级 / 文件名格式是下载时的选项（D-55/58）。

**US-17 写入安全**
- 输出先写同目录临时文件，成功后再以不覆盖方式落位；失败或取消时清理临时文件。
- 单个文件写入失败只标记该文件，不中断整批。

**US-18 方向归一**
- 读取 EXIF 拍摄方向并按 8 种方向正确旋转/翻转。
- 输出文件不依赖方向标签即可正确显示。
- 没有方向信息的图片保持原样。

**US-19 隐私剥离**
- 输出不包含 GPS、相机型号、拍摄时间等 EXIF 信息。
- 首版不保留 ICC 色彩配置；输出是全新编码，不复制源文件元数据块。
- 标记“已跳过”的源文件不修改、不复制，因此不会被剥离元数据。

**US-20 透明铺底**
- 透明图转 JPEG 时，透明区域铺白底。
- 队列中给出“透明背景已铺白”的提示。
- 输出 PNG/WebP 时保留透明通道。

**US-21 动图拒绝**
- 多帧 GIF/WebP 标记失败，原因写明“首版不支持动图”。
- 不静默取第一帧；同批其它文件继续处理。

**US-22 目标体积达成**
- JPEG/WebP：优先搜索满足上限的最高编码质量；仍超标时逐步缩小尺寸。
- 首版不设质量或尺寸下限；极端降级只提示，不失败。
- PNG：不做有损质量搜索，只通过更高压缩级别与缩小尺寸达成目标；不做调色板量化。
- 目标体积低到任何编码都无法满足时，该文件失败且不输出。
- 成功的文件必须满足：输出体积 ≤ 目标体积，且输出尺寸在宽高盒内。

**US-23 尺寸盒缩放**
- 输出尺寸等比放入宽高盒；不裁切、不拉伸。
- 源图小于盒子时不放大；若没有其它规则则该文件走“已达标”逻辑。

**US-24 已达标跳过**
- 当源文件已满足目标体积与宽高盒，且不需要格式转换时，标记“已达标”，不产出新文件。
- 该行为不修改源文件，也不执行元数据剥离。
- 队列仍显示源文件信息与“已达标”状态。

**US-25 极端降级提示**
- 在目标体积搜索中，最终编码质量 < 20，或为达标把长边缩到 < 128 px（且该尺寸小于用户设置的宽高盒；未设置宽高盒时同样计为降级）时，队列标黄并显示“已明显降质”。
- 提示不阻断输出；批次汇总中统计极端降级数量。

**US-26 失败继续与汇总**
- 单张失败不中断批次；失败项显示原因。
- 批次结束汇总成功/失败/跳过/取消数量、总节省体积。
- 每个失败都写入日志（路径 + 原因），日志不包含图片内容。

**US-27 节省统计**
- 成功项显示原体积、输出体积、节省比例；若输出更大则显示负节省。
- 批次总计显示累计节省字节与百分比。

### D. 预览与对比

**US-28 单张对比**
- 选中成功项后，可查看原图与结果图的并排或切换对比。
- 显示两侧尺寸与体积。
- 首版不做缩放、拖拽、滑动对比与像素级检查。

**US-29 预览渲染**
- 预览按方向归一后的像素显示。
- 透明图预览使用棋盘格背景。
- 预览由 Go 生成并通过绑定传给前端；不为任意本地路径开放 HTTP 静态服务。

**US-30 结果过期**
- 参数或队列改变后，已有处理结果标记为“结果已过期”。
- 开始新批次时清除旧结果状态并重新处理当前有效项。

### E. 平台与交付

**US-31 三平台产物**
- macOS：`.dmg`，可通过 `make package os=macos` 产出。
- Windows：NSIS `.exe` 安装器，可通过 `make package os=windows` 产出。
- Kylin/Linux：`.deb` 安装包，必须包含 GTK/WebKit 运行时依赖声明。
- 三平台版本号同源于 `wails.json` 的 `info.productVersion`。

**US-32 Kylin 安装与启动**
- `.deb` 可在银河麒麟 V10 SP1（2203，x86_64）安装。
- 应用可启动，原生文件对话框、拖拽、日志、配置读写正常工作。
- 含中文、空格与较长名称的路径可正常导入与输出。

**US-33 Kylin 冒烟**
- 在真实麒麟机器上安装 `.deb`，启动应用。
- 导入至少一张 JPEG 与一张 PNG，设置目标体积与宽高盒各处理一次。
- 输出文件生成、对比预览可用、源文件未被修改、无网络请求。

**US-34 Kylin 关闭行为**
- 关闭窗口不得出现“窗口消失且无法恢复”的状态。
- 若麒麟托盘经 spike 验证可用，可选择隐藏到托盘；否则关闭即退出。
- Windows 保留关闭隐藏到托盘；macOS 关闭即退出。

**US-35 产品身份**
- 显示名称为“图片工坊”，可执行文件/英文标识为 `ImageWorkshop`。
- 应用数据目录、日志名、单实例锁均使用 ImageWorkshop 标识，不再使用 `file-processor`。
- 不迁移旧脚手架的数据；首次启动创建新目录。
- macOS bundle id 保持占位值 `com.example.imageworkshop`（2026-10 修订：个人与朋友分发，不办证书不做公证，占位值无实际影响；若未来正式分发再统一收口，见 D-32）。

**US-36 本地与离线性**
- 运行时不发起网络请求，不上传图片，不采集遥测。
- 断网环境下可完成导入、处理、对比与预设管理。

**US-37 安全上限与资源**
- 单张输入上限：100 MP 像素、512 MB 文件；超过则标记失败并说明原因。
- 批次并发默认 2 个 worker，避免在 16 GB 机器上因大图并发导致 OOM。
- 单张解码/缩放失败只影响该文件。
- 队列在处理期间保持可响应。

**US-51 信创 arm64 构建产物（2026-10-24 增补）**
- CI 每次构建产出 `ImageWorkshop_<版本>_arm64.deb`（飞腾/鲲鹏），经 amd64 容器内 clang/lld 交叉构建（ADR-0006）。
- 仅作为 CI artifact，不接 Release、不宣称可用——真机验收前与「能跑」严格区分（D-45）。
- `make linux-deb arch=arm64` 本地等价可用（需 Docker）。

### F. 应用入口与设置

**US-38 工作台入口与导航**
- 应用启动后直接进入“图片处理”工作台；默认路由指向它。
- 侧栏提供“图片处理”和“设置”；设置页保留主题、数据目录、版本、日志与数据库导出。
- 不再出现“仪表盘”占位页。

### G. 输出目的地、命名与队列内重跑（2026-10-24 增补）

**US-39 选择输出目的地**
- 可选「源文件同目录（默认）/ 自定义目录平铺 / 自定义目录并保留导入时的文件夹结构」；默认行为与历史版本完全一致。
- 自定义目录不存在时自动创建：非法目的地在规则预检（US-11）报错；目录创建失败在批次开始前报错——此时未处理任何文件，不浪费转换（2026-10-24 审阅修订：创建由批次入口统一执行，而非逐项编码后再失败）。
**US-40 保留文件夹结构**
- 「保留结构」以导入根为基准重建目录层级；多根导入各自保持相对层级，同名同路径靠序号后缀防覆盖。
- 相对路径不可信（含 `..` 或绝对路径）时该项失败，绝不写出输出目录之外。
**US-41 命名模板**
- 模板变量 v1 仅 `{name}`（原词干）与 `{n}`（队列序号）；必含其一；禁路径分隔符与 `..`；长度 ≤ 64。
- 界面实时预览渲染效果；冲突防覆盖序号规则与 US-16 一致。
**US-42 输出设置持久化**
- 输出目的地三项（模式/目录/模板）随「上次设置」防抖落盘并重启恢复；预设不携带（D-34）。

**US-43 重跑失败与未完成项**
- 批次结束后可一键重跑全部「失败」与「已取消」项；成功/跳过项的既有结果原样保留。
- 重跑以当前规则与输出计划发只含目标项的子集批次；结果只合并回这些项；汇总从队列项派生而非只信最后一次批次结果。
- 重跑受单批次互斥与取消语义约束；不落任何历史——清空队列即消失（D-38）。
**US-44 单行重跑**
- 失败/已取消行可单独重跑；处理进行中禁用。

**US-52 首屏隐私声明（2026-10-24 增补）**
- 空队列拖拽区与设置页可见与本机处理承诺一致的隐私说明。
- 文案与 README 首句逐字同口径：改隐私文案需 README / 空态 / 设置页三处同步（D-46）。

**US-49 自动最小格式（2026-10-24 增补）**
- 输出格式可选「自动（最小体积）」：逐项从 JPEG/WebP/PNG 候选跑完整转换（含目标体积搜索），取输出体积最小者，行内注明「自动选择 XX（最优）」。
- 全部候选都无法达标时该张失败且不产出；透明→JPEG 铺白候选照常参与并随所选结果打标（D-43）。
- 选项文案如实标注较慢（每项最多 3 次完整编码）。

**US-45~48 单张调参工作台（2026-10-24 增补）**
- US-45 进入工作台：队列中任一已检查图片可打开调参弹窗；批次处理进行中禁用（D-41）。
- US-46 实时试算：改规则后防抖自动重算（PreviewConvert），体积/尺寸/质量/标志位为真实编码结果；已达标明确说明「不会产出文件」；试算永不写盘。
- US-47 滑块对比与放大：源图与当前规则输出拖分割线对比，1–4 倍同步缩放（预览级，D-40）；透明区域棋盘格。
- US-48 应用与沉淀：「应用到全部」回写工作台参数（触发结果过期标记）或「存为预设」（复用 SavePreset 校验）；两者都不自动开始批次。
- US-50 工作台竞速：调参弹窗内一键按当前规则分别试算 JPEG/WebP/PNG 三格式，表格列出体积/质量/尺寸，最小体积行高亮，点选行即采用该格式（自动复核试算）。

### H. 普通用户化：人话文案、暂存与下载、历史记录（2026-10-24 增补，ADR-0007）

**US-58 人话文案**
- 界面词汇以根目录 `GLOSSARY.md` 为单一真相（「常用设置/无需处理/画质变差了/再试一次/单张试一试…」），Go 返回的提示与结果文案同一张表；改词先改 GLOSSARY。
- 代码标识符不改，只改用户可见字符串。

**US-59 处理只进暂存区**
- 处理结果一律写入应用数据目录的暂存区（`history/<一次处理>/`），**原图所在文件夹零写入**；忘了保存，应用重开也还在。
- 「无需处理」的原图不产出、不落暂存。

**US-60 下载（保存）**
- 下载是唯一落盘出口：结果列表每张成功图「下载」按钮，汇总条「全部下载（n）」；两者共用一个选项框（D-58）。
- 选项框：保存位置（默认系统「下载」文件夹，记住上次选择）+「保留原来的文件夹层级」+ 文件名格式（带实时示例）；确认后才保存。
- 重名不覆盖（-2/-3），原子落位；下载是复制，暂存原件保留、可反复保存。

**US-61 下载完成反馈**
- 保存完成提示「已保存 n 张到 xxx」+「打开文件夹」入口；结果行「已保存」标记（本次会话）。

**US-62 历史列表**
- 侧栏「历史记录」菜单：一次处理一条——时间、人话设置摘要、张数（已完成/失败/无需处理/已取消）、累计节省。

**US-63 历史明细与再次保存**
- 点开看每张图：缩略图（源图删了也在）、前后大小、状态与原因、是否保存过；成功且未清理的可再「下载」/「全部下载」。

**US-64 历史保留与清空**
- 保留最近 30 次处理的可下载暂存（启动与每次处理后自动修剪）；更早的条目保留记录、标「图片已清理」、不可再保存。
- 设置页显示暂存占用，可一键「清空历史记录」（二次确认）。

## 5. 测试决策

### 5.1 接缝与单元测试

**`internal/imageproc`（纯函数，主测试靶心）**
- 用真实生成的图片 fixture，不用 mock 图片。
- 覆盖：JPEG/PNG/WebP 互转；BMP/TIFF/静态 GIF 输入；损坏文件；扩展名与内容不一致（按内容处理）。
- 覆盖：8 种 EXIF 方向；方向归一后的像素与尺寸。
- 覆盖：透明 PNG → JPEG 白底；PNG/WebP 保留透明。
- 覆盖：宽高盒等比缩放、不裁切、不拉伸、不放大小图。
- 覆盖：目标体积搜索（输出 ≤ 上限；质量优先；必要时缩尺寸；极端降级标记；不可达目标失败）。
- 覆盖：PNG 目标体积仅缩尺寸、不做量化。
- 覆盖：输出无 EXIF/GPS/ICC 元数据。
- 覆盖：动图检测（GIF 多帧、WebP ANIM）。
- 覆盖：100 MP / 512 MB 上限。
- 覆盖：默认质量 85 的编码路径。

**`internal/service`（文件系统与编排）**
- 用临时目录与真实文件，不用 mock 文件系统。
- 覆盖：递归扫描、隐藏/符号链接规则、去重、排序。
- 覆盖：批次成功/失败/跳过/取消混合；继续处理；汇总计数。
- 覆盖：输出命名与冲突序号；源文件字节不变；无临时文件残留。
- 覆盖：取消后当前文件完成、未开始项取消、无半成品。
- 覆盖：预设 CRUD、名称唯一、上次设置往返。
- 覆盖：中文/空格/长路径。

**护栏**
- 新增绑定方法使用 `apperr`；`app.go` 不直接 import gorm/database。
- 新模型（预设）登记进 `AllModels()`。
- 新依赖登记进 `deps.yaml`，双向校验通过。
- 事件域/动作与前端镜像由 `internal/guard/parity_test.go` 覆盖（若新增常量）。

### 5.4 完成定义

一个切片完成需同时满足：
- 该切片的自动化测试通过，`make test` 与 `make lint` 通过。
- 受影响平台可构建；涉及 UI 的切片在真实应用里操作过。
- 不覆盖源文件、失败不产生半成品、事件订阅可解绑。
- Kylin 相关切片必须附真机或 spike 证据。
- 新依赖已在 `deps.yaml` 登记。

## 7. 补充说明

### 7.1 目标环境证据

用户提供的麒麟机器信息：
- 系统：银河麒麟桌面操作系统 V10（SP1），版本号 2203。
- 内核：Linux 5.4.18-53kt-generic。
- CPU：Hygon C86 3250，8 核；架构 x86_64。
- 内存：16 GB（可用约 9.1 GB）。
- 桌面：UKUI。

因此默认并发 2、单张 100 MP 上限，优先保证不 OOM。

### 7.2 技术风险与 spike

1. **纯 Go WebP 有损编码器**：已由 002 spike 验证，采用 `gen2brain/webp` v0.6.4 + `nodynamic` 构建标签；后续升级该库时需重新验证纯 Go 后端与体积/alpha 行为。
2. **Go 1.25 编译 WebP 库会失败**：`gen2brain/webp` 的 2.6MB 转译源在 Go 1.25 下冷编译 516s、2.245GB 时被 kill（原因未确认为 OOM 还是工具内存限制）；Go 1.26.2 冷编译 34.9s、898MB。已定 D-33：构建基线升到 Go 1.26，由 003 落实。
3. **Kylin WebKit 版本**：默认 4.0 还是 4.1 必须由 spike 的 `dpkg` 结果决定；现有 `package.sh` 固定 `webkit2_41` 不能直接用于麒麟。
4. **Kylin 托盘**：energye/systray 依赖 appindicator；UKUI 下可能不可用。关闭行为必须先保证可退出。
5. **打包依赖**：`.deb` 的 Depends 必须与实际链接的 GTK/WebKit 一致；未验证前不得宣称支持。
6. **代码签名**：v1 不做 macOS 公证与 Windows 签名；首次运行可能被系统拦截，需在交付说明中写清。

### 7.3 依赖决定（002 spike 结果）

- 构建基线：**Go 1.26.x**。Go 1.25 无法在可接受的内存/时间内编译 WebP 依赖；003 升级 `go.mod`、CI 与 README。
- `github.com/gen2brain/webp` v0.6.4（MIT）：WebP 有损/无损编解码、alpha、动图；构建带 `nodynamic`，不加载系统 libwebp，使用内置 WASM 转译的纯 Go 后端。
- `golang.org/x/image` v0.45.0（BSD-3，要求 Go 1.25）：BMP/TIFF/WebP 静态解码与 CatmullRom 缩放；升级到要求 Go 1.26 的新版本前需单独评估。
- EXIF 方向：在 `internal/imageproc` 实现最小容器解析（JPEG APP1 / PNG eXIf / WebP EXIF / TIFF IFD0），覆盖大小端与 8 方向；不引入外部 EXIF 库。
- 动图检测：WebP 扫描 `ANIM`/`ANMF` 块；GIF 计数图像描述符；不整段解码所有帧。
- `purego` 是 `gen2brain/webp` 的间接依赖，`nodynamic` 下不编译/不链接。
- 005 已将 `gen2brain/webp` 与 `golang.org/x/image` 引入 `go.mod` 并登记 `deps.yaml`；Wails 与 Go 测试统一带 `nodynamic` 构建标签。
- 已否决：`HugoSmits86/nativewebp`（仅无损）、CGO libwebp（破坏无额外 CGO 目标）、`dsoprea/go-exif`（130 个依赖，功能远超方向解析所需）。

### 7.4 身份与发布

- `productName`：图片工坊；`outputfilename`：ImageWorkshop；内部 `appName`：ImageWorkshop。
- 构建基线：Go 1.26.x；`go.mod`、CI `setup-go`、README 三处一致。

### 7.5 已确认的默认假设

1. 无目标体积时默认质量 85。
2. 无有效规则禁止开始；已达标且无需转换/缩放的图片不另存。
