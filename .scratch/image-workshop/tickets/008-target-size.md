# 008 — 目标体积

**Blocked by**: 007

**规格**: US-09、US-22、US-24、US-25、US-27；D-07、D-08、D-09、D-24

## 目标

用户设置文件体积上限后，系统优先搜索满足上限的最高编码质量，仍超标则缩小尺寸；输出不超过上限。极端降级标黄提示但仍输出；任何编码都无法满足时该文件失败且不产出。

## 涉及层

- [x] 数据层：无数据库。
- [x] 逻辑层：JPEG/WebP 质量搜索；必要时逐步缩小尺寸；PNG 使用更高压缩级别并缩尺寸，不做调色板量化；不设质量/尺寸下限；极端降级标记（质量 <20 或长边 <128，未设置盒时也算）；目标体积优先于宽高盒；源文件已满足目标体积与盒且无格式变更时跳过；不可达目标返回失败；批次汇总统计极端降级与节省体积。
- [x] UI 层：目标体积开关、数值输入、KB/MB 单位；范围 1 KB–1 GB 校验；逐项显示输出体积/是否达标/极端降级黄色徽标；批次汇总显示极端降级数量与失败原因。
- [x] 测试：输出 ≤ 上限；优先保留最高质量；质量到底后缩尺寸；极端降级阈值；不可达目标失败且无输出；PNG 只缩尺寸；目标体积 + 宽高盒；已达标跳过；无下限路径；前端手动验证。

## 验收标准

- 目标体积可开启，单位 KB/MB，范围 1 KB–1 GB；与宽高盒可同时启用。
- JPEG/WebP 先搜索最高可用质量；仍超标再缩尺寸；PNG 用更高压缩级别并缩尺寸，不量化。
- 成功输出满足：体积 ≤ 目标上限，且尺寸在宽高盒内；体积与尺寸冲突时体积优先。
- 极端降级（质量 <20 或长边 <128；未设置盒时也算）标黄提示，但仍输出并计入汇总。
- 目标体积低于任何可编码下限时，该文件失败且无输出；其余文件继续。
- 源文件已满足体积与盒且无格式变更时标记“已达标”，不产出、不修改源文件。
- 批次汇总包含成功/失败/跳过/取消/极端降级数量与节省体积。
- `make test` / `make lint` 通过；macOS 手动验证通过。

## 完成记录

- 状态：完成（2026-10-23）
- 实现说明：
  - 引擎：`ConvertOptions` 增加 TargetBytes；JPEG/WebP 用二分搜索满足上限的最高质量，质量 1 仍超标则按体积比例缩尺寸并重试；PNG 用 BestCompression + 缩尺寸，不做量化。最终尺寸仍在宽高盒内；极端降级由引擎标记（质量 <20，或目标驱动的缩尺寸使长边 <128；无盒或低于用户盒均计），`Converted` 回传 Quality/ExtremeDegraded；1×1 仍不达标返回可读错误。
  - 批次：允许 1 KB–1 GB 目标；源文件体积已 ≤ 目标、在盒内、无格式变更时标记已达标不落盘；目标与盒冲突时体积优先；单张不可达失败继续；汇总增加极端降级数量，节省只统计成功项。

- 偏离与遗留：
  - 质量二分假设编码体积随质量基本单调；若遇到编码器局部非单调，可能不是数学上的最高质量，但仍保证 ≤ 目标。
  - 缩尺寸使用体积比例启发式；不设质量/尺寸下限，极端情况会持续缩小直到达标，极端降级只提示不阻断。
  - UI 目标下限 1 KB；引擎本身支持更小目标（测试用 800B/50B），但通过 UI 不会出现 <1KB。
  - 目标下限很低时多数格式可在 1×1 达标；不可达失败路径由引擎真实测试覆盖。
  - 队列状态仍是页面本地状态，路由切换会丢失；作为后续审计项。
